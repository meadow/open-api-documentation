---
title: Checkout Handoff
description: Send customers to a Meadow checkout page to complete their order
---

Build your own shopping experience and hand the customer off to Meadow to check out. Meadow's checkout page handles pricing, discounts, loyalty, payment and placing the order.

## Prerequisites

- An integration with the **Create Orders** and **Customers** [permissions](/permissions)
- Product option IDs from the [menu](/endpoints/menu/list-menu)
- To send customers back to your site or app, the dispensary sets your [authorized domain or app URL scheme](#customizing-the-checkout)

## How it works

1. Your server creates a cart with the customer's line items.
2. When the customer clicks checkout, your server mints a handoff token for the cart.
3. You redirect the customer to the `checkoutUrl` that comes with the token.
4. The customer pays and places the order on Meadow's checkout page.
5. Meadow sends the customer back to you, and you look up the order.

Orders are your integration's, like orders created with [POST /api/v1/orders](/endpoints/orders/create-order): your integration's discounts apply, and its settings decide the order's status, inventory location and delivery zone.

<Note>
  Orders are created as **drafts** unless the dispensary turns on **Orders are created with the status: "new"** for your integration (Settings > API Integrations, then **Edit**). Drafts don't reserve inventory or notify the dispensary's staff until they're accepted, so most dispensaries using checkout handoff will want it on.
</Note>

## Step 1 - Create a cart

Create the cart with [POST /api/v1/carts](/endpoints/carts/create-cart).

```javascript
{
  "type": "pickup",
  "userId": 4821,
  "continueShoppingUrl": "https://example.com/shop",
  "autoSuccessUrl": "https://example.com/checkout/complete",
  "lineItems": [
    {
      "productOptionId": 1899,
      "quantity": 3
    }
  ]
}
```

A delivery cart needs a full address the dispensary delivers to. To change the line items before checkout, use [PUT /api/v1/carts/\{cartId\}](/endpoints/carts/update-cart).

## Step 2 - Mint a handoff token

When the customer clicks checkout, mint a token with [POST /api/v1/carts/\{cartId\}/access-token](/endpoints/carts/create-access-token).

```javascript
{
  "data": {
    "accessToken": "Xq3v8kR1mJ2p9sT0wY5zA7bC4dE6fG8hI0jK2lM4nO6",
    "expiresAt": "2026-10-28T16:05:00.000Z",
    "checkoutUrl": "https://embed.getmeadow.com/organizations/12/h/checkout/01999c4e-3a7b-7c2d-9e1f-4a5b6c7d8e9f?access_token=Xq3v8kR1mJ2p9sT0wY5zA7bC4dE6fG8hI0jK2lM4nO6"
  }
}
```

The token expires after 5 minutes and works once, so mint a new one each time the customer checks out.

## Step 3 - Redirect to the checkout page

Send the customer's browser to `checkoutUrl` with a `303 See Other` redirect or `window.location.assign()`. Don't show it as a link the customer could copy, since it contains the token. Query parameters you add, such as `utm_source`, are kept.

## Step 4 - Return to your site

| Field | Where the customer goes | If it's not set |
| --- | --- | --- |
| `continueShoppingUrl` | The checkout page's **Continue Shopping** button | The authorized domain |
| `autoSuccessUrl` | Straight after placing the order | Meadow's order confirmation page, with a link to `continueShoppingUrl` |

Both must be on your authorized domain or in your app URL scheme.

## Step 5 - Look up the order

[GET /api/v1/carts/\{cartId\}](/endpoints/carts/retrieve-cart) returns the cart's `orderId` once the customer has checked out. Follow the order with [GET /api/v1/orders/\{orderId\}](/endpoints/orders/retrieve-status).

# Customer and guest carts

| Cart | Set | Notes |
| --- | --- | --- |
| Customer | `userId` | The order is placed for the customer, with their discounts and loyalty. Find customers with [GET /api/v1/customers/\{identifier\}](/endpoints/customers/retrieve-customer). |
| Guest | `customerName`, or none | Pickup only. The dispensary must allow anonymous pickup orders, otherwise creating the cart returns `ANONYMOUS_EMBED_ORDERS_NOT_ENABLED`. Without a `customerName`, the checkout page asks for one. |

# Mobile apps

Create the cart and mint the token on your server, never with API keys in the app. Then open `checkoutUrl` in:

- **An in-app browser** (`SFSafariViewController` or `ASWebAuthenticationSession` on iOS, Custom Tabs on Android). Use an `autoSuccessUrl` in your app URL scheme, such as `myapp://orders/complete`, to come back to your app.
- **A WebView**. Use an `https` `autoSuccessUrl` and close the WebView when it navigates there.

Use your app URL scheme rather than universal links or App Links for `autoSuccessUrl`: operating systems usually only open apps from links the customer taps.

# Customizing the checkout

Each integration has its own settings. The dispensary manages them in Meadow under **Settings > API Integrations**, by editing your integration.

| Setting | Default | What it does |
| --- | --- | --- |
| Authorized domain | None | Your site's domain, e.g. `example.com`. Web URLs on a cart must be on it or a subdomain. Without it, a web URL returns `INVALID_PARAMS`. |
| App URL scheme | None | Your mobile app's scheme, e.g. `myapp`, for URLs like `myapp://orders/complete`. |
| Foreground color | `#000000` | Text and icons |
| Background color | `#ffffff` | Page background |
| Accent color | `#00b2ff` | Buttons and links |
| Error color | `#f44336` | Error messages |
| Corner radius | `5` px | Buttons, inputs and cards, 0 to 24 |
| Button style | Fill | **Fill** or **Border** |

### Trying out an appearance

Preview any appearance with sample products by adding the settings to the preview URL:

```
https://embed.getmeadow.com/organizations/{organizationId}/h/checkout/preview?colorAccent=%232e7d32&colorBackground=%23fdf6e3&uiCornerRadius=12&uiStyle=border
```

The parameters are `colorForeground`, `colorBackground`, `colorAccent`, `colorError` (write `#` as `%23`), `uiCornerRadius`, `uiStyle` (`fill` or `border`) and `type` (`pickup` or `delivery`).

For a quick try on any checkout page, open your browser's developer tools, select the `<html>` element and edit `--color-foreground`, `--color-background`, `--color-accent`, `--color-error` or `--corner-radius`. Shades worked out from these, such as hover colors, won't update.

### Asking the dispensary

Send the dispensary your authorized domain, your app URL scheme if you have an app, and the appearance you'd like, e.g. as a preview link. A Meadow admin with full permissions updates them on your integration.

# Constraints

- **Tokens:** a handoff token expires after 5 minutes and works once. Opening `checkoutUrl` without a valid token shows "Checkout link expired": mint a new token, the cart is unchanged.
- **Keep tokens private:** until it's used, a token lets anyone check out the cart as that customer. Only send it to the customer's browser, and don't log it.
- **One checkout per cart:** a cart can only be ordered once. Create a new cart for the next order.
- **Revoked access:** if the dispensary deletes your integration or removes **Create Orders** or **Customers**, its carts can no longer be checked out.
